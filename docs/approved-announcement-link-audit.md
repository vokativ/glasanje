# Approved recipient announcement links — 12 September 2026

This records the earlier 101-entry snapshot. The subsequent [remaining mission collection audit](remaining-mission-collection-audit.md) adds the newly reviewed recipients, Latvia's Sweden coverage and the release coverage comparison.

Reviewed all 101 approved public entries (34 source-confirmed, 67 operator-approved), grouped by their 41 responsible missions/consulates. Existing ministry coverage resolution and operator decisions were retained. This was a targeted source-link audit, not a new recipient promotion run.

38 missions now have maintained links to 36 distinct current official announcements. Those links reach 90 approved entries, including dependent non-resident countries. For 83 entries the relevant mission's published mailbox appears in the notice text; Mexico and its six dependent countries have a current registration notice without a mailbox in the retrieved page text. The remaining 11 approved entries depend on Paris, Nairobi and Yerevan. On 13 September the maintainer confirmed that those missions have no announcement; they are now marked accordingly.

The addresses, approval states, station IDs, mission identities and coverage relationships are unchanged for all 223 public stations. Links are stored in `data/overrides.json` under the existing station's `electionNotice`; public JSON and TypeScript are regenerated together. Each record carries the actual notice URL, title, election year, observation time and extracted-email status. Existing approval provenance is unchanged. No candidate packets, source archives, AI reviews or approvals were created by this audit.

## Findings that matter for collection

- Start with existing approval provenance: many direct announcement URLs were already present there but were not exposed publicly.
- Vienna's navigation says **Избори 2026**, but the target is `/gradjani/najcesca-pitanja`. Read link text and the page, not just the URL slug. It explicitly gives `izbori.bec@mfa.rs` for electronic submission.
- Minsk, London and Oslo's stored `www` URLs failed TLS hostname validation during retrieval. Their non-`www` official pages opened successfully and contain the maintained recipient. The new public notice pointers use those working URLs; historical approval records remain intact.
- Canberra's joint announcement names Canberra and Sydney separately; Rome's announcement includes a separate Malta submission section. Reuse the actual joint publication without merging those recipients.
- Canberra and Pretoria explain submission by email and then name their mission mailboxes as election-information contacts. Preserve the maintained operator decisions and full context; do not manufacture a new automatic confirmation.
- Mexico's notice explicitly lists Mexico, Honduras, Costa Rica, Panama, Nicaragua, El Salvador and Guatemala. Its HTML body contains registration instructions and links to two Word forms but no mailbox. The HTML image is a data-URI placeholder with no notice image URL. The linked forms were not downloaded in this audit. Publish the notice as registration guidance; keep the separate operator authorization of `embajadaserbiaenmexico@gmail.com`.
- Notices describe where people will vote (including travel to the mission), and some have distinct document or local-time instructions. A covering mission's link does not promise a polling place in each covered country or create new territorial coverage. Readers can inspect the original instructions directly.

## Website and verification

The official notice link is shown beside the approval message on the status page, the selected-mission card, and the final submission/contact screen. The final-screen unconfirmed warning also links to an available notice. An entry marked `not-published` says the mission has not published an election announcement, including for resolved covered countries. Existing recipient confirmation remains unchanged. Other missing links still use the generic link-not-added message. All links open the institution's page in a new tab; no archive is required.

Validation: `bun run build:data`, 86 passing Python tests (including maintained-link and no-archive build regressions), `bun run check`, and 62 passing application tests. Headless Chrome checks covered Austria, all six German missions, New Zealand, Malta, Mexico, Monaco, Georgia, Uganda and Bulgaria; desktop/mobile screenshots were inspected and no horizontal overflow was found. A semantic comparison against the pre-change branch snapshot checks every station ID and every non-notice public field, including resolved non-resident entries. This is a local baseline, not a deployed-release baseline; no deployment was performed.

## Future option: internal source archive

Consider retaining a dated copy of each selected announcement and relevant attachment/image, with the original URL, so a later redesign or removal of the institution's page does not erase the historical evidence. An archive could supplement the live source link and preserve earlier election instructions as history. This is a future option only: the current work stores links and metadata, does not build an archival service, and does not make archived copies a prerequisite for published recipient approval.
